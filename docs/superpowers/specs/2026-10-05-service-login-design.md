# Service login

Add one administrator username/password to the Area Target service on the current published baseline (2e21f90). Server-side authorization covers every route, including static pages, old APIs, mobile v1 APIs and future routes. Only /login, POST /api/auth/login and GET /healthz are public. Missing credentials fail closed. This authorized task includes browser and iOS clients so cloud uploads remain usable after authentication is enforced.

Password configuration uses AREA_TARGET_USERNAME and a Werkzeug scrypt hash AREA_TARGET_PASSWORD_HASH generated interactively; no production password is committed. Login verifies a bounded JSON body, applies SQLite-backed rate limits before hashing, and issues a random 12-hour session. Store only its SHA256 digest, expiry and credential fingerprint; logout removes the session. Credential changes invalidate earlier sessions. The browser receives an HttpOnly, Secure, SameSite=Strict cookie and a separate CSRF token. All browser mutations require CSRF. Native clients persist only their opaque session in Keychain and send X-Area-Target-Session, preserving the existing per-job Bearer token and ownership checks.

Health checks move to /healthz. CI configures temporary credentials and smoke-tests anonymous rejection, login, upload, processing and downloads. Production Compose requires credentials and retains the private optimizer network. Local Compose exposes only localhost:8080. Deployment must keep existing volumes, host routing and memory settings; publishing alone does not change Portainer. Verify production configuration and perform live authenticated/anonymous checks after rollout.
