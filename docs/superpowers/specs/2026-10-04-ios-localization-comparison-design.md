# iOS Area Target 定位测试与算法对比

状态：方向已确认。用户在看到真实 native 引擎接入、共同评价与冻结同帧对比建议后，明确要求“下一步”集成空间识别算法到 iOS，实现同样的流程并比较评分。按该要求继续实施。用户所说的“平分”按“评分”理解。

## 目标与现有成果

Area Target 与 Immersal 都提供选择扫描、上传建图、下载、本机定位测试、保存和分享测试报告的流程。同一个扫描记录可以用于两种建图方式，并对同一段新的现场测试帧进行公平对比。

Area Target API 已发布到 https://area-target.p.01xr.com，iOS 上传、处理、下载、SHA256 校验和本机保存已经完成真实线上联调。该部分保持可用；新增工作是本机定位、共同评价和对比工具。

## 推荐方案与替代方案

推荐：保留两种算法各自的现场离线测试，另外增加“同扫描对比”。对比模式先采集未参与建图的新测试帧，冻结灰度像素、内参、AR 相机位姿、时间和帧编号，再依次重放到两个引擎。两个引擎收到相同有效帧，成功率分母相同，定位耗时不含另一个引擎的排队时间。

替代：分别现场测试后比较两份报告。接入更简单，但光照、路线、姿态和帧内容不同，只能比较两次测试表现，不能称为同输入公平比较。

不推荐同时运行两个引擎：虽然图像可以相同，但 CPU 竞争影响耗时。因此正式比较采用分开重放。

## 本机定位与坐标

Area Target 使用仓库内真实 native_visual_localizer：ORB、BoW 检索、描述子匹配、PnP RANSAC。接入只读 features.db reader 和 OpenCV；不以 stub 或假返回值代替定位。

现有 Immersal SDK 已静态包含部分 OpenCV 符号。Area Target/OpenCV 应封装在独立 native framework 内，只暴露 vl_* C API，避免把两套 OpenCV 实现混入同一静态符号空间。实施的第一关是两引擎在同一 App 的真实链接与符号隔离验证；失败时先解决隔离，不交付只能载入文件的假定位入口。

数据库载入检查表和列、描述子 BLOB 长度、点数量、有限数值、资源上限及必要非空数据。native 创建、载入、定位、重置、释放串行执行，使用 vl_process_frame_out 避免结构体返回 ABI 问题。

两个 adapter 输出 AR 相机坐标下的 cameraFromAsset 刚体矩阵。Area Target 返回 row-major T_C_S，native 已执行 CV→AR 转换；Swift 只还原行列布局，worldFromScan = worldFromCamera × T_C_S。Immersal 单独执行现有相机轴转换和求逆，不复用到 Area Target。

现场测试复用相机预览、原扫描 OBJ 网格叠加、开始/停止和报告分享。原扫描模型不存在时显示固定测试标记；定位依赖已下载特征库，不依赖原扫描照片。无需新增 GLB 渲染依赖。

## 输入身份、校准与公平性

两种资产绑定共同的原扫描身份和内容 fingerprint，记录各自资产摘要、建图参数和引擎版本；不同导出 ZIP 的 SHA 不直接视为同一扫描 fingerprint。历史资产缺乏可靠版本关联时明确标记，不能自动声称同输入比较。

对比帧来自一次新的、连续正常跟踪的 ARSession，训练照片不能作为测试成绩。采集内存和图像尺寸有限制；不足条件时仍可查看原始指标，但不生成总分。切到后台、追踪重置或取消会结束当前段，不混合不同 AR 世界的数据。

首版最多采集 32 帧，采样间隔至少 1.5 秒，紧密灰度像素总量上限 96 MiB；长边最多 1920 像素，必要时等比缩小并同步缩放内参，不裁剪。到达容量后结束采集，保留已完成的合法段并提示用户。两引擎使用完全相同的归一化像素。采集原始图像不写入导出的报告。

Immersal 用原扫描照片估计 mapFromScan，以便两种结果都统一为 worldFromScan。校准照片不计成绩。评分前重新载入或重置引擎，避免校准造成预热或改变首次检索状态。校准失败时仍可展示成功率和耗时，不能给出包含共同原点稳定性的总分或优劣结论。

报告注明采集与重放方式、执行次序、采样规则和 cold/warm 状态。对比不比较两个厂商含义不同的 confidence，不向定位引擎额外提供 ARKit 真值位姿。

## 指标与评分

共同指标：尝试数、成功率、首次识别、定位耗时中位数/P95、共同扫描原点下的对齐平移/旋转变化、测试时长和 AR 相机累计移动距离。首次识别的采集时间位置与重放实际计算耗时分别记录，避免把离线重放时间冒充现场响应时间。

数值总分称为“本次定位表现分”，公式版本化，0–100 分：成功率占 40 分，P95 定位耗时占 20 分，P95 对齐平移变化占 20 分，P95 对齐旋转变化占 20 分。后面三项采用 min(1, 基准阈值/实测值) 计分，零值按满分处理，缺失项为零。基准沿用当前筛查规则：3 秒、0.25 米、5 度。零成功总分为零。

至少 20 次共同有效尝试、30 秒连续采集、3 米有效 AR 相机累计移动后，才提供对比总分；需要足够成功结果及可靠共同坐标校准才评价稳定性。样本不足、校准不完整或资产版本不明时明确显示原因，原始指标仍可查看。保留阈值结论和各项指标，不把一个总分当成完整优劣结论。

稳定性至少需要两次有效成功定位；Immersal 共同扫描坐标校准至少需要三张一致的训练照片，沿用 60% 共识、0.25 米/5 度的现有校准门槛。达到共同采样条件而零成功的引擎显示零分和“未能识别”；存在成功但不满足稳定性或共同坐标条件时暂不提供完整总分。公式缺失项为零只用于无识别结果，不能补造未知的稳定性成绩。

对齐变化衡量重复定位稳定性，不是真实世界的绝对精度；本次报告仅代表本次空间、采样位置、光照和设备。不能从一段测试宣称算法普遍更优。

## 界面与存储

Area Target 下载成功后增加“测试定位”入口；两种平台均显示共同指标和数值评分。扫描记录提供“对比两种算法”，只允许关联同一原扫描的可用本机资产。

对比模式显示采集进度、两个引擎的重放进度、并排指标及各自评分。测试照片只用于本机计算，报告不包含照片、凭据或 GPS；用户可以保存和导出报告。新的报告结构版本化，保留现有 Immersal 报告可读性，不改变无关工作。

## 验收

1. 真机目标成功编译，Area Target/OpenCV 与 Immersal 在同一 App 的符号隔离和真实链接通过；原生已知姿态夹具能成功定位，包含坐标布局和轴转换检查。
2. Area Target 资产下载后能载入数据库，现场测试的生命周期、错误和取消行为与 Immersal 一致。
3. 共同评分覆盖成功、全部失败、缺样本、计时、百分位、对齐、校准失败及跟踪重置。
4. 对比测试证明两个引擎接收相同帧、分母一致、校准不计成绩且不污染冷启动，失败不被跳过，旧报告保持可读。
5. 原有扫描、Immersal 与上传下载测试继续通过，原有无关未提交文件保持完整。
6. 模拟器和合成夹具证明连接与数学契约；真实空间定位表现必须由真机现场采样报告给出，不编造实测优劣。
