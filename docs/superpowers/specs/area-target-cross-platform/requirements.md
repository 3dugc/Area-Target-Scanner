# Area Target 跨平台 SDK 需求

日期：2026-10-05（Asia/Shanghai）。状态：用户已确认架构方向，本组文件同时维护执行合同；当前执行 M0/M1 与最小测试迭代工具。

事实来源：本次用户确认的设计、当前 `native_visual_localizer/`、iOS 原生定位实现、Unity Runtime，以及 Immersal 的公开 SDK 组件文档。新的跨平台范围独立于旧 `phase-1-ios-workflow`；旧计划中的未完成设备验收继续有效，不能由新架构或编译结果代替。

## 目标与边界

当前执行限制（2026-10-05）：先完成M0基线与M1通用C++核心，随后通过现有iOS最小测试入口持续验证识别准确率、稳定性并迭代算法。M2–M5仅保留路线，暂不执行。新增S01任务交付固定数据回放、同输入基线/候选比较、独立验收与失败样例回归方法；真实数据不足时明确未测，不以合成夹具声明真实准确率提升。优先复用工程自带 94 帧建图数据与 64 帧待核对会话；旧元数据仅用于诊断回归，独立精度验收由后续 iOS 新采集补齐。

将现有 C++/OpenCV 定位算法整理为可以被 Swift、Kotlin/JNI 和 Unity 调用的共享定位 SDK。优先完成 iPhone/iPad、Android 和 Rokid，再按具体型号的相机能力接入 PICO、Quest。建图工具、资产分发、定位算法、跟踪融合、设备采集和应用场景分别承担明确职责。

扫描端保留现有 LiDAR 工作流；定位端以已下载的特征地图、相机图像和校准数据为基本条件，不要求定位设备具备 LiDAR。连续稳定显示还需要可同步的设备跟踪位姿。不能将“支持某品牌”理解为该品牌的全部型号已经通过验证。

## 必须遵守的数据合同

1. `T_A_B` 始终表示 B 到 A，列向量左乘；C ABI 矩阵以 row-major 数组保存，长度固定 16。存储转置和坐标基转换是两种操作。
2. `S` 保留已知扫描生产者的右手地图坐标，单位米。v2 的 `C` 为右手光学坐标：X 向右、Y 向下、Z 向前。`W` 为适配器规范化后的右手跟踪坐标。原生 v2 输出 `T_C_S`；融合计算 `T_W_S = T_W_C × T_C_S`。
3. 原有 `vl_*` 仍返回当前 AR 相机约定的 `T_C_S`，保持既有轴转换、结构和行为。v1 与 v2 结果不能混用。
4. v2 第一期仅接受已校正的 Gray8 图像。提供真实 buffer 长度、宽高、row stride 和当前图像对应的内参。畸变、裁剪、缩放、旋转或镜像由可测试的校准组件处理；未知校准数据不得以零畸变代替。
5. 时间戳包含源时钟/epoch、曝光时间和规范化的单调时间。不得用 UI 当前时间、读取时间或人为 `+1ns` 冒充曝光时间。
6. 跟踪数据可选。融合必须具备同帧或可验证插值的 `T_W_C`、时钟映射和有效的相机外参。无跟踪数据可继续 Raw 定位；无相机图像/内参则不能宣称视觉定位可用。
7. 结果包含 frame ID、采集时间、地图世代、地图实例、模式、有效性和拒绝原因。无结果的矩阵不具有有效位姿语义；调用方不得把 identity 当作成功定位。
8. 图像、地图加载、融合和过滤的资源与阈值策略均版本化。成功率、稳定性、算法置信度和绝对精度分别报告。

## 兼容、范围与不包含内容

- 复用现有 C++ 算法；本计划不替换为 Rust，不引入新的学习型特征或自研完整 SLAM。
- 本计划不增加地图拼接、跨楼层地图联合搜索、共享多人锚点、全品牌全型号支持或 Web 定位。
- Python/Docker 建图保持独立；不重新设计扫描 ZIP、服务器账号、支付、云部署或 Immersal API。
- 新格式描述通过宿主资产元数据兼容既有地图；不能为了核心迁移强制用户重新扫描或改写已有数据库。
- 本地 `model_optimizer` 版本漂移只进入 M0 基线核对；恢复版本或迁移服务 API 是独立集成工作，不能暗中并入 SDK 任务。
- 保留用户现有未提交工作。实现从经核对的集成基线建立隔离 checkout，并明确带入哪些任务差异；不得自动拉取后覆盖当前目录。

## 支持声明的等级

| 等级 | 可以声明什么 | 不足以证明什么 |
|---|---|---|
| 架构覆盖 | 已定义接口和适配路径 | SDK 已构建、设备可用 |
| 构建通过 | 对应 ABI/平台实际编译和链接成功 | 相机可访问、现场定位成功 |
| 算法接通 | 已知姿态夹具与跨宿主回放通过 | 真实空间中的精度与稳定性 |
| 设备试用 | 指定型号、OS、SDK、地图通过现场闭环与 30 分钟运行 | 全部型号可用、商业目标达标 |
| 商业验收 | 指定设备与数据集达到已记录的质量目标 | 任意环境均具有同样表现 |

设备试用门槛沿用三处 20–100 m² 场地。iPhone、iPad 各需独立运行记录；其他正式支持的设备型号同样需要三个场地的定位、失锁恢复、离线重启、暂停恢复和各 30 分钟运行。不同宿主采集路径也必须有闭环证据。

商业质量目标沿用既有商业化设计：平移误差 ≤10 cm、旋转误差 ≤3°、初次定位 P90 ≤3 s、重定位成功率 ≥95%、应用渲染 ≥30 FPS、连续两小时无崩溃或持续内存增长。绝对误差需要独立标定的真值及其不确定度；这些是验收目标，不是当前能力声明。
