# 实现设计

## 采集与地图

新增独立灰度质量函数，按固定最长边约 160 像素抽样，计算 Laplacian 方差、灰度标准差及曝光饱和比例。初始保守门槛：方差 8、标准差 6、均值范围 12–243、极端灰度比例 95%；这是待现场校准的起点。拒绝原因固定可诊断，不保存被拒绝画面为地图帧，不影响已有点云累计。Swift 读取 Y 平面，不旋转/裁剪/改变 K；质量测试覆盖清晰纹理、模糊、黑白曝光和重复位姿。

采集至少间隔 0.2s；满足已有 0.5s 或 0.10m，或朝向变化 15°时检查质量并采集。质量拒绝不推进最后成功关键帧状态。ScanProgress 新字段提供默认值以兼容旧构造；现有进度页显示质量反馈，并明确路径面积不是视觉覆盖。

Python 新 `keyframe_quality.py` 仅解码、调用 C ABI 并写诊断；灰度质量及覆盖选帧唯一实现位于 C++ `gray_quality.cpp` 和 `keyframe_selection.cpp`。先检查全部原始视角，再选移动端最多80帧，原始 image_id 不重排。质量合格且未超预算时全保留；贪心覆盖以平移/1m、旋转/30°残差结合质量，最后按原索引排序。无有效位姿时采用时间覆盖，不从坏 pose 生成非法距离。底层 `build_feature_database` 旧默认不变；`OptimizedPipeline` 启用版本化质量选帧并在 manifest/cache 配置声明。相同像素、位姿、预算输出确定。全源检查设20亿像素累计解码上限，在解码前拒绝超预算任务，原始上传保留；80帧、1600长边与2亿处理像素预算不变。

## 恢复

ORB 快路径附近候选失败后扩展现有 BoW 全局 Top30，去除重复候选。ORB 不足或无法检索时，AKAZE 以每次最多 30 个的稳定轮转批次尝试；reset/load 清空轮转状态。恢复仍使用现有匹配/PnP 验证，最终失败仍 LOST，C ABI 不变。

## 统一 C++ 核心（用户补充后采用）

复用现有 `codex/area-target-runtime-v2` 的 `area_target_runtime.h`、Raw、SQLite reader 和 `LocalizationSession`；这些源码与当前 OpenCV 5、恢复补丁合并，不能带回旧 4.x 依赖。各平台从同一份 C++ 编译产物，保留旧11个 `vl_*` 入口并增加版本化 `atc_*`，实际部署的库同时提供兼容入口与共享Session，不能加载两份不同算法实现。

Swift、C# 和 Python 入口只做FFI，核心承担灰度质量、采集触发、覆盖选帧及 Immersal 静态网格对齐共识。灰度采样覆盖采样步长的空间相位，避免单相位抽样误删高频有效纹理。Swift/C# 原本的位姿门控、初始化、丢失降级和平滑迁入共享C++ Session。既有独立Swift policy仅作为已写行为合同的迁移参考，最终不保留实现。静态网格共识保留原3帧、60%、0.25m/5°及实际观测medoid合同，参数从C++默认配置读取。

Raw 使用v2光学相机轴，宿主明确做一次 optical↔AR/Unity 坐标转换；同帧图像、内参、pose、camera ID、时间基/epoch、map generation绑定仍为桥接职责。Core/Session 不调用平台API。

共享Session支持同步 update 与每帧 poll；poll只更新结果年龄和显示有效性，不推进视觉frame ID或制造Raw成功，防止在途结果被伪帧挤掉。迟到检查在同一个C++入口接受单调交付时间，时间和阈值定义保持唯一。默认配置由核心提供可显式覆盖的工程profile，实际现场门槛仍需验证。

## 对齐行为合同

共享 `LocalizationSession` 输入 Raw `T_C_S`、同帧 `T_W_C`、序号、单调时间及身份。默认工程起点 2 次确认、0.25m/5°一致范围、3s 最大结果年龄与 3s 保持上限；按时间而非失败帧数过期。复用已有平移与旋转残差及四元数插值，平滑参数以时间常数表示，不在不同设备复制固定权重。

状态：searching/candidate/confirmed/degraded/lost。大跳变只建立新候选，不直接替换可靠锚点；未确认候选不能重置旧锚点有效期。无效/过期/乱序结果不写对齐历史。ARFrame tick 检查过期；generation、跟踪中断、地图切换、stop/start 清空历史。Area Target 与 Immersal 使用各自 policy 实例；统一 policy 不合并两地图结果或分数。

当前默认平滑使用时间常数2s、平移插值与旋转最短弧四元数插值，作用于地图对齐变换，不重复平滑平台提供的相机运动。此策略替代旧C#的6维位置/欧拉角卡尔曼实现，并非将卡尔曼原公式原样迁入C++。这是当前低频绝对定位输入的工程选择；响应速度、抖动及绝对精度仍须同数据 A/B。以后若增加可信速度、IMU和观测协方差，可在同一核心内评估误差状态滤波，桥接接口保持一致。

使用可注入 systemUptime 时钟，生产与 ARFrame.timestamp 相同时间基；合成测试显式注入时钟，生产不自动修正虚构时间。原始 evaluation 仍记录引擎每次输出，持有旧锚点不添加视觉成功。SDK 二进制、相机轴转换及网格父子变换不变。

## 工作区与验证

原工作区未提交文件已备份并 SHA256 记录。隔离工作区覆盖这些文件以验证当前完整 App，新增改动按覆盖层基线计算增量，不提交已有用户功能和私有 SDK。回归采用实际 OpenCV 5 CTest、Python、Swift Simulator 与 Unity EditMode；实际 SDK device link 验证 coexistence。部署原生二进制必须与 C++ 源码对应。

现场验收仍使用独立查询/负样本、同预算地图 A/B、遮挡与跨区域恢复、控制点精度及持续功耗。当前缺少此数据，不填造收益数字。
