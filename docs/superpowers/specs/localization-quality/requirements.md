# 第一阶段：采集、恢复与跨帧稳定

依据：用户于 2026-10-05 接受 `docs/localization-improvement-roadmap.md` 的第一阶段路线，并要求实际实施。基线为 develop `802e1bb`，隔离分支 `codex/localization-quality`；当前未提交 iOS 功能作为兼容验证覆盖层，不能随本任务整体提交或覆盖。

1. 采集：只有正常跟踪且画面可读时记录关键帧；识别明显模糊、曝光饱和、缺少纹理，显示跳过原因与计数。新增朝向变化触发，限制过密重复采集，重启/跟踪批次改变时清空选帧历史。图像、内参、姿态、时间和 run 保持同帧绑定。
2. 地图：优化管线使用可重复的画面质量与空间/朝向覆盖选帧；保持原始 image_id、同一帧的特征/3D 对应及移动端 80 帧、2000 ORB/500 AKAZE 预算。保留底层旧选择模式用于 A/B；记录选择版本和诊断，改变缓存身份，不能复用旧地图当新结果。
3. 恢复：低 ORB 特征可进入独立 AKAZE；附近候选全部失败后尝试未测试的全局候选。AKAZE 无 ORB 检索时使用有上限、可轮转覆盖全部关键帧的批次。白图/错误地图仍不能凭回退返回成功。
4. 统一 C++ 对齐：Unity、iOS 使用同一套 C++ Core/Session 和质量策略实现，各自维护独立句柄。两个一致的新鲜刚体结果才确认；平移/旋转门控、平滑、失锁恢复、时限降级、迟到/逆序/无效结果拒绝及 epoch/map 重置全部在 C++，不保留 Swift/C# 算法副本。每帧通过桥接 poll 检查过期，即使定位任务卡住也不能无限显示。
5. Unity/iOS 桥接：仅负责设备取帧、校准与坐标转换、单调时钟/身份传入、串行生命周期和显示；失败帧不能读取失败结果 pose，降级零新视觉证据。Immersal 原 SDK 是外部后端，其输出可接共享 C++ Session，但不修改或宣称统一其私有识别实现。
6. 兼容：保留 OpenCV 5、11 个 native C ABI、现有 PnP/Hamming 门槛、Immersal SDK 原包及坐标转换、原始视觉评测分母/成功率。所有新增数值为可回滚工程起点，软件测试通过不代表现场识别率或精度提高。

2026-10-05 用户补充的架构约束优先于初始设计：只有一个自有 C++ 定位算法实现，Unity 也调用它，所有定位相关优化在核心中进行。复用 `codex/area-target-runtime-v2` 已有版本化 `atc_*` Core/Session；保持 `vl_*` 兼容入口及原字节布局。旧 Swift policy 和 C# Kalman/对齐算法从活跃路径移除，避免多处调优。

不包含：学习模型、ICP/SfM、Immersal SDK 升级、云定位、发布、真机安装、其他设备 SDK 接入。Python 仍承担离线建图和任务编排；新增画面质量与覆盖选帧调用共享C++实现。网络、资产下载、UI和平台跟踪采集不进入算法核心。
