# Immersal 地图下载与离线定位测试

## 使用

Immersal 模式 → 处理 → 建图任务 → 选择已完成的任务 → **下载地图与离线测试**。
下载时使用当前账号从官方服务获取地图；完成后可断开网络，点击 **开始离线测试**。
回到实际扫描过的空间，对准有纹理的固定物体，缓慢走动并改变朝向，建议测试 60–90 秒。
开始时会读取这项建图任务对应的原扫描 OBJ，并用最多8张原扫描关键帧离线核对模型坐标。至少3帧且60%的有效匹配在0.25米/5°内一致才启用叠加；这些旧图不计入现场质量报告。
首次现场识别成功后，相机画面叠加青色网格线；观察墙角、门框、地面边缘是否重合。可以开关网格并调节透明度，模型保持原始尺寸。未匹配或中断时隐藏网格，避免旧位置误导。
如果原模型/照片缺失、扫描含不同追踪批次或坐标核对不足，界面会说明原因，现场定位仍可继续，使用蓝色测试标记作为回退。
点击 **结束并保存本段测试**，可以查看和导出 JSON 报告，也可以导出 `.bytes` 地图。
切入后台、相机追踪中断或退出页面会结束当前段，重新测试会使用新的相机跟踪坐标系。

## 报告含义

- 成功率：独立现场相机帧中成功匹配目标地图的比例；只统计相机正常追踪时的尝试。
- 首次定位：从首个有效尝试开始到首次成功结果返回，包含推理时间，排除下载、加载和相机准备。
- 定位耗时：全部有效尝试的中位数和 P95，含成功及失败尝试。
- 对齐位置/角度变化：连续相机跟踪段内，相邻成功结果对地图与跟踪空间对齐关系的变化；不是绝对精度。
- 已测试走动：成功匹配之间的 AR 相机累计位移；不是地图覆盖率。

经验筛查需要至少 20 次尝试、30 秒、3 米有效匹配间走动。达到样本条件后，成功率至少 80%、首成功不超过 10 秒、P95 耗时不超过 3 秒、P95 对齐平移变化不超过 0.25 米且角度变化不超过 5°，显示本次表现稳定。这些是本 App 公开的试用筛查阈值，不是 Immersal 官方精度指标；阈值随报告保存。足量尝试仍零成功会明确提示未识别到空间。

没有现场实测时不生成报告或质量分数。自动化测试中的合成报告只用于检查数学和界面，不能作为用户地图质量结论。现场还应在不同位置、朝向和光照下重复测试；绝对定位精度需要额外真值测量。

## 实现边界

- 官方 `POST /mapb64`，凭据仅放请求正文；下载最大 64 MiB，验证 Base64 和官方 SHA-256。
- Application Support 中按账号/地图 ID 分区，内容哈希命名及原子 descriptor 发布；重新读取时再次校验。报告跟随具体地图内容哈希保存。
- `.bytes` 由官方原生 iOS arm64 静态库读取。库固定在 Immersal SDK 2.4.0；[来源与许可说明](../ios_scanner/AreaTargetScanner/ThirdParty/Immersal/README.md)。模拟器只能验证界面和流程，不能执行原生定位。
- 独立 ARSession，同一采集帧的灰度图、内参、位姿一起送入本机引擎；正确处理像素行步长和相机坐标轴，所有加载、定位、释放串行执行。
- 定位阶段没有云端定位调用，不上传测试图像，也不保存这些相机图像。
- 叠加使用既有扫描 `model.obj`，不要求 GLB，不读取纹理。原文件保持不变；几何分段读取以减少大模型的文本内存占用。
- 对齐矩阵明确使用 `worldFromMap × mapFromScan`，不把外部地图元数据/ECEF变换当作本地扫描坐标。校准不拟合缩放，不能修复原始网格漂移。视觉错位也可能来自扫描网格本身的误差。
- 下载/删除本机任务不会修改云端地图。下载后的地图不会自动进入 Area Target 流程。
