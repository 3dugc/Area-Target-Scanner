# iOS 直接上传 Immersal 与建图

## 使用

1. 首页进入「Immersal 账号与任务」，使用 Immersal 邮箱和密码登录。App 只将邮箱、用户 ID 和 Developer Token 保存到本机 Keychain，不保存密码，也无需手动填写 Token。下次启动会恢复登录；Token 失效后重新登录。
2. 完成扫描，或从历史记录进入预览，点击「上传到 Immersal 并建图」。原有两种 ZIP 导出入口继续保留，上传无需生成 ZIP。
3. 上传页使用原生 SwiftUI「准备 → 上传 → 建图」分阶段引导，底部根据当前状态展示一个主操作。准备页确认扫描时间、帧数和地图名称（1–24 个英文字母或数字），点击主按钮后检查扫描帧、账号、容量和工作区。云端已有图片时自动显示实际数量和本次帧数；明确确认「清空并上传 N 帧」后逐帧上传，全部确认后自动建图。
4. 上传期间保持 App 在前台。顶部「完成」可返回扫描页面；底部「稍后处理」会暂停本机上传后返回。进入后台会暂停本机上传，回来后在任务页继续。已提交的云端建图持续运行，App 在前台每 5 秒查询状态。
5. 上传阶段显示实际已确认帧数，建图阶段显示云端状态；未开始上传时不显示空进度条。页面默认展示短地图名称；完整文件名、云端名称、地图 ID 和完整任务提示在「更多 → 扫描与任务详情」中查看。历史任务通过「历史」独立查看，选择任务后回到该任务的当前阶段；账号及停止本机任务从更多操作进入。也可打开 [Immersal Portal](https://developers.immersal.com/) 查看结果。退出登录会暂停本机上传并删除 Keychain 凭据；原账号任务和扫描仍保留，重新登录原账号后可查看。

上传内容包括扫描图片、相机内参和位姿，以及扫描时保存的 GPS（缺失时为零）；不会重新采集当前位置。旧记录缺少完整逐帧信息或方向未经验证时，Immersal 上传与导出均不可用，Area Target 原格式仍可导出。保留现有模型、纹理、预览、GPS 与历史功能；OpenCV 仍为 4.x。

## 工作区与恢复

- Immersal 的图片工作区属于账号，同一账号的其他设备会共享它。上传期间不要在其他设备或 Portal 上传、清空工作区或提交建图。图片数检查可以发现数量冲突，不能证明工作区图片内容完全一致，也不能防止其他设备并发修改。
- 工作区图片数与本机记录不一致时，立即弹出清空确认，显示云端实际图片数和本次帧数。只有用户明确确认「清空并上传 N 帧」后才调用 `/clear`；会删除全部工作区图片，包括锚点及其他设备上传的图片，已有地图不受影响。确认前再次检查数量；若已变化，重新显示最新数量并询问，不直接清空。
- 「暂不上传」、关闭页面、进入后台或退出账号都会撤销当前提示，不删除扫描或云端图片。历史记录的重传操作先只读查询最新图片数再询问，兼容未保存数量的旧记录；取消后可重新检查并重试。
- 请求发出前先持久保存操作意图。帧上传或清空响应丢失时，不盲目重发该帧；需要明确确认清空工作区后从第一帧重传。已确认帧之间暂停时，可核对工作区后继续剩余帧。
- 建图响应丢失或数据库结果不确定时，按唯一名称和帧数查询 `/list`，找回地图 ID；不会再次自动提交 `/construct`。未查到结果不代表服务器没有接收，需在 Portal 核实。长期无法核对时，可以明确确认「停止本机跟踪」，保留记录及不确定提示并解除本机任务限制；这不会取消云端任务，之后重新上传有可能产生重复地图。
- 本机任务写入失败时停止发送；记录损坏时阻止新上传和源扫描删除，避免遗忘云端进度。源图片内容变化、坏图或坏元数据会明确报错，不跳过帧。
- 在任务仍需要源数据期间禁止删除对应扫描。可以对允许停止的任务选择「停止本机任务」；这不会删除本地扫描或已经上传到工作区的图片。任务记录按账号隔离；其他账号的未完成任务也会保护对应源扫描。

## 实现合同

实现依据 [官方 REST API](https://developers.immersal.com/docs/rest-api/) 与 [官方 Python 示例](https://developers.immersal.com/docs/rest-api/python-example/)。请求固定发送到 `https://api.immersal.com`，使用 HTTPS POST，禁止自动跟随重定向；不在 URL、日志、扫描目录或 ZIP 写入凭据。

| 接口 | 用途 |
| --- | --- |
| `/login` | `login`（邮箱）和 `password` 换取用户 ID 与 Token |
| `/status` | 核对账号、图片数与每地图图片容量 |
| `/capture` | UTF-8 JSON + 一个 NUL 字节 + PNG 二进制；不使用 ZIP 或 Base64 |
| `/clear` | 用户确认后清空账号工作区，`anchor=true` |
| `/construct` | 全部帧确认后建图，固定 `preservePoses=true`，使用提交的相机位姿优化建图 |
| `/list` | 查询本机发起任务的云端状态，或找回未收到的建图结果 |

帧数据复用 [双格式导出合同](ios-dual-export.md)：原始 JPEG 转 8-bit RGB PNG，保留尺寸和像素方向，使用已验证的 ARKit→Immersal 位姿转换；逐帧保留 run/index/GPS。上传 JSON 移除本地 `imagePath`，仅发送时加入 Token。预检查一次一帧，不保留所有 PNG；上传时按内容摘要核对源图并转换。

任务记录位于 App 私有 `Application Support/Immersal/jobs.json`，原子写入并排除备份，包含账号 ID、源扫描名、内容摘要、帧数、已确认进度、待确认操作、唯一地图名称、地图 ID 和状态，以及可选的工作区图片数量，不含 Token/密码。Keychain 项使用 `WhenUnlockedThisDeviceOnly`，不启用 iCloud 同步。

## 验证边界

本次全量 XCTest 共 **169 项通过**，覆盖扫描、导出及模拟网络上传状态机，包括自动数量提示、取消、数量变化后重新确认、旧记录兼容、过期提示保护与不确定请求恢复。实际 SwiftUI hosting 与 fake API 生成的本地截图还验证了原生 `UIAlert` 工作区确认自动呈现；该截图场景只有模拟 `/status` 请求，没有触发 `/clear` 或 `/capture`。

最终签名构建通过，已覆盖更新到连接的 iPhone 15 Pro 并成功启动；最终本地截图检查通过。上述验证不使用真实账号、不实际上传扫描数据，**不代表真实 Immersal 云端上传、建图或真机点按已通过**。最新结果见 [工作区确认与界面实施记录](superpowers/plans/2026-09-30-immersal-workspace-confirmation.md)，此前的直接上传实现见 [实施记录](superpowers/plans/2026-09-30-immersal-direct-upload-tasks.md)。

后续云端验收需用户在真机 App 自行登录并选择扫描：验证首次/再次登录、少量实拍帧上传与建图状态、地图 ID、断网/后台恢复、退出与账号切换、工作区清空确认，以及历史扫描删除保护。工作区清空应使用专门的测试账号或确认不再需要的工作区。
