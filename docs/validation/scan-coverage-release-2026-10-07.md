# 扫描优化发布记录（2026-10-07）

本次发布包括已完成的 OpenCV 5 升级，以及扫描预处理 v2 的保守去重、自适应分辨率、均衡特征预算、有界 UV 和临界帧保护。发布基线合并远端 develop 的任务保护与已验证升级提交 `802e1bb`，保留双方历史；未纳入工作区中的其他 Immersal、跨平台定位与 Unity 功能改动。默认能力档为 100，500 继续作为部署及独立现场验收目标。

## 发布组合验证

- Python 3.11 / OpenCV 5.0.0：与 Deploy 相同的 27 个模块，393 通过、1 个本机未启用的原生 xatlas helper 测试跳过。三项 KMeans 收敛警告来自合成重复描述子。补充升级集成 20 项通过，最终 smoke 检查 27 项通过（含两项伪造/缺失服务器选择摘要反例）。
- 新发布目录从源码构建 OpenCV 5.0.0 macOS 原生库，4/4 契约测试通过。未复用工作区中的完整新定位运行时二进制。
- iOS main scheme 三类测试：122 项（121 通过、1 项真实夹具默认跳过）；显式 94 帧真实归档另跑 1 项，通过。迁移后的 10 个 Swift/project/bridge 文件及 6 个质量内核文件逐个 SHA 相同。
- 实际 94 帧双 ZIP：全部上传，保护源序号 47–54，18 个风险候选。86 张普通编码与对照一致，8 张保护图保留原始 JPEG 字节；源摘要、ID、位姿、时间与逐轴内参核验通过。图像 payload 与此前公平 CG 回放完全一致。
- 最小 Docker 上下文实际导出仅 6 个质量内核文件，与原实现逐字节一致。
- v1 默认选帧保留已发布的均匀策略；默认 requirements 字段集合恢复原合同。v2 的去重能力只在显式协商分支声明。旧任务及保存 ZIP 重试继续使用冻结策略和字节。

Linux/amd64 实际镜像 HTTP 冒烟验证已通过：实际 OpenCV 5.0.0 和预编译 `/app/bin/libarea_target_quality.so`。4 帧上传后去重为 3 帧，数据库保留 2959 个 ORB、500 个词；保护帧特征坐标达到 x=1887、y=1408，确认保留高于普通 1600×1200 的实际图像信息。客户端和服务器选择/缩放摘要均校验通过。此测试使用本机已有兼容优化器镜像；CI 将重新构建固定 gitlink 优化器并验证发布镜像。

新增 `--preparation-v2` 容器 HTTP 冒烟测试：验证明确协商、全部 4 帧上传、重复视角 3→2、实际选中 3 帧、混合尺寸及保护帧、保存的客户端/服务端 provenance、三维特征及数据库预算。原有 v1 两项冒烟测试继续保留。CI 还增加三类 iOS 测试及六个新增 Python 测试模块；镜像必须通过真实运行验证后才推送仓库。
